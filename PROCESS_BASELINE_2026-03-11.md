# Process Baseline – Artifact Session Packaging

Date: 2026-03-11

## Purpose

This document records the first stable operational workflow for generating and packaging research artifacts from an AI-assisted development session.

The goal of the system is to create a reproducible pipeline where engineering work produces structured artifacts that can later be analyzed by research agents.

This baseline reflects the validated workflow after the LiveView research UI prototype session.

---

# System Model

The system operates in two loops:

### Loop 1 – Artifact Capture

Engineering sessions generate structured artifacts describing the work performed.

```
implementation work
        ↓
artifact generation
        ↓
artifact ledger
```

Artifacts capture **what happened during a session**.

These artifacts are immutable and stored under:

```
artifacts/sessions/<session-id>
```

---

### Loop 2 – Research Extraction

Research agents analyze session artifacts to extract cross-session patterns.

```
artifact ledger
        ↓
research analysis agent
        ↓
research knowledge base
```

Research notes represent **interpretation of artifacts**, not the artifacts themselves.

Research outputs are written under:

```
research/
    observations/
    experiments/
    questions/
    snapshots/
    synthesis/
```

---

# Repository Structure

The research repository contains three conceptual layers.

```
ai-systems-research
│
├── artifacts
│   └── sessions
│
├── research
│
└── contracts
```

## artifacts/

Machine-generated outputs describing individual sessions.

Example session package:

```
artifacts/sessions/<session-id>/
    analysis_prompt.md
    system_snapshot.md
    lesson_learned.md
    complexity_inflection_points.md
    strategy_context_reduction.md
    research_bridge.md
    request_log.json
    session_reasoning_graph.json
```

These files describe the **decision flow and architecture state of a specific work session**.

Artifacts must never be edited after creation.

---

## research/

Cross-session knowledge generated by research agents.

Categories:

```
experiments
observations
questions
snapshots
synthesis
```

These documents represent conclusions drawn from multiple artifact sessions.

---

## contracts

Documents that define the artifact schema and research workflow.

Key files:

```
ARTIFACT_SCHEMA.md
RESEARCH_CONTRACT.md
CHAT_SESSION_PROMPT.md
START_HERE.md
SYSTEM_INDEX.md
```

Contracts define how artifacts are created and interpreted.

# Artifact Session Packaging Workflow

The validated workflow for packaging a session is:

### Step 1 – Implementation Work

Development occurs in an implementation repository.

Example:

```
liveview/ui
```

Artifacts are generated by an analysis agent and written to:

```
research-output/
```

---

### Step 2 – Package Artifacts

Artifacts are copied into the research repository.

```
artifacts/sessions/<session-id>
```

A script (`package-research-session.ps1`) automates this process.

The script performs:

1. capture implementation repo commit
2. capture repo tags
3. copy `research-output`
4. update `request_log.json`
5. append `SESSION_LOG.jsonl`
6. stage artifacts for commit

---

### Step 3 – Session Ledger Update

Each session must append an entry to:

```
SESSION_LOG.jsonl
```

Example entry:

```
{
  "session_id": "2026-03-11-liveview-ui",
  "system": "liveview",
  "focus": "research UI prototype analysis",
  "artifact_path": "artifacts/sessions/2026-03-11-liveview-ui"
}
```

The session log acts as the **discovery boundary for sessions**.

---

### Step 4 – Commit Artifact Session

The research repository commits the session artifacts.

Example commit:

```
research session: liveview research UI prototype analysis 2026-03-11
```

# Architectural Principles

## Artifact-First Research

Artifacts are the source of truth.

Research conclusions must always reference artifact evidence.

---

## Immutable Session Evidence

Session artifacts must not be edited after creation.

Corrections must occur in later sessions.

---

## Reproducibility

Every session must record:

* implementation repo
* commit hash
* repository tags
* analysis prompt

This ensures sessions can be reproduced.

---

## Strict Discovery Boundary

`SESSION_LOG.jsonl` defines the canonical session index.

Research agents should discover sessions only through this log.

---

# Known Refinements From This Session

1. Prompts used for artifact generation must be preserved as artifacts (`analysis_prompt.md`).

2. Artifact envelopes should eventually be validated strictly at load time.

3. Renderer logic should treat payload mismatches as telemetry rather than errors.

4. Artifact packaging should be automated with a session packager script.
